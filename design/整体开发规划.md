# 牛牛农场 · 从测试原型到完整游戏 · 整体开发规划

> 依据：`design/Stacklands式卡牌经营游戏_GDD.md`（v0.1 paper prototype）
> 配套：现有 `src/`（Vite + 原生 ES Module，无框架）
> 纪律：模糊形容词不进规划；每个阶段都有"坏掉长什么样"的验证闸门；所有未经 playtest 的数值标 `[PLACEHOLDER]`。

---

## 0. 结论先行

当前 `src/` 已经是一个**可玩的垂直切片**：

- 拖拽堆叠交互成立（P1 操作极简已验证）
- `drag.js + merge.js + checkMerge` 做了方向敏感命中，未命中弹回、无惩罚（保护探索欲，符合 GDD 4.1）
- 单条"员工→资源→牛→卖钱→买包"生产链跑通，日循环结算不崩

但它还**不是 GDD 定义的游戏**——缺配方探索、缺生存压力、缺战斗、缺长期留存，经济也没有闸门。

**核心立场：不要推倒重来。** 把现有代码当作"核心交互 + 一条示范生产链"的地基，向上叠加 GDD 的七套系统。**品牌「牛牛农场」保留，主体必须围绕牛（用户拍板 2026-08-18）**：recipe 引擎以牛链为中央支柱，经济硬币唯一主源 = 卖牛；木材/围栏/银行卡链为存储与辅助，不 1:1 复刻 Stacklands 浆果起点（见 GDD §7 修订）。

## 2. 总体演进策略

- **地基不动**：`state.js`（数据层）/ `merge.js`（规则纯函数）/ `systems.js`（业务）/ `render.js`（渲染）/ `drag.js`（输入）/ `modals.js`（弹窗）分层合理，沿用。
- **新增 recipe 引擎**（关键一步）：把现在硬编码在 `merge.js` 的 `comboInfo` 规则，抽成数据驱动的 `recipes` 注册表（`inputs → output + duration + isIdea`）。这既承接 GDD 4.2，也顺手让现有牛链可配置化。
- **术语对齐**：`day → moon`、`employee → villager`、`burger → food`（保留 burger 作一种 food）、`money/bank → coin`（统一为 GDD 硬币）。只改内部命名与文案，不改玩法。
- **增量叠加**：每阶段只加一套系统 + 一个 playtest 闸门，阶段间保持可玩。

  - `config.js`：`DAY_LEN` 改名 `moonLength`；新增 `MOON_LENGTHS = {新手:90, 老兵:45}` `[PLACEHOLDER·待 playtest]`；加难度选择入口。

### 阶段 1 · 配方引擎 + 卡牌图鉴（约 2–3 周）— 交付 P2 探索驱动

> 前置：阶段 0 已完成（命名/结算对齐）。本阶段即**选项 C**。

- **目标**：把"任意两张卡叠一起都会发生点什么"从口号变成引擎；玩家靠实验发现配方。
- **交付**：
  - 新建 `recipes.js`：数据驱动注册表 `RECIPES = [{inputs, output, duration, isIdea, unlocks}]`，首版录入牛链 + 浆果链 + 木材链约 10–15 条。
  - `merge.js` 的 `comboInfo` 改为查 `RECIPES`（保留方向敏感作为部分配方的 `direction` 约束）。
  - 首次命中未知组合 → 生成 Idea 卡 + 写入 Cardopedia。
  - 新建 `cardex.js` + `localStorage`：已发现配方跨局永久保存（交付 P4 长期成就感）。
  - **Sequence breaking 允许**：未解锁也能手动拼出成品（GDD 4.2 edge case）。
- **验证**：探索信号——前 10 个核心配方至少 6 个由玩家自主触发发现；Cardopedia 刷新后仍在。
- **改动文件**：新增 `recipes.js`, `cardex.js`；改 `merge.js`, `drag.js`, `render.js`, `systems.js`, `index.html`（图鉴入口）。
- **PLACEHOLDER**：各配方 `duration` 先用假设值（参考现有 2s 产出），进 GDD §6 登记。

### 阶段 2 · 经济闸门与卡位（约 2 周）— 交付 §7 通胀论证

- **目标**：给"卡→币→包→卡"正反馈环加安全网，防止 board 拥挤/死锁（非通胀主刹车，见下方前置结论）。
- **前置已完成（B · Monte Carlo）**：`design/MonteCarlo_cardCap结论.md` 已交付——推荐 base `cardCap = 60`（`[PLACEHOLDER·待 playtest]`），`cardCapPerShed = +20`、`cardCapPerWarehouse = +50`。关键洞察：本设计 board 是**硬币约束**而非卡位约束，cardCap 在牛-centric 里几乎不触顶（稳态 ~20 卡），其真实角色是防死锁安全网。
- **交付**：
  - `Economy` 模块：`cardCap`（基础 **60** `[PLACEHOLDER]`）、`cardCapPerShed`、`cardCapPerWarehouse`。
  - 棚子/仓库建筑卡：放置即 `+cardCap`（GDD 4.7）。
  - **Dustbin 卡（必须同期落地，优先级提升）**：销毁不可卖卡，防死锁——无 Dustbin 时 board 填满即死锁（GDD 4.7 failure state）。
  - 食物腐坏计时器 `spoilTimer` `[PLACEHOLDER]`：生肉等易腐品超时变废料。
- **验证**：C 信号已降级为**警告**（本设计近不可能通胀，见 GDD §7 修订）；改监测后期 board 占用率目标 40–70%，偏离则回调 `cardCap` / 包价梯度。
- **改动文件**：新增 `economy.js`, `montecarlo.mjs`；改 `config.js`, `systems.js`, `render.js`, `modals.js`, `index.html`（卡位计数）。

### 阶段 3 · 生存张力与战斗（约 3 周）— 交付 P3

- **目标**：把无限扩张的人口变成风险，制造"喂饱人 vs 扩张"的月度张力。
- **交付**：
  - Moon 末 `maybeSpawnMonster()`：非和平模式按节奏刷怪（GDD 3.2）。
  - 战斗系统：空闲村民自动迎战；武器卡（矛/剑/枪）叠村民 `+ATK`；HP/ATK/克制表 `[PLACEHOLDER]`。
  - 人口繁殖：2 村民 + 房子 → 婴儿 → 长大（GDD 4.5 source）。
  - 战斗死亡 = 永久死亡（双 sink 之一）。
- **验证**：B 信号——前 3 月饿死率 10%–70%；不在区间则调 `moonLength`/食物产出。战斗 playtest 测"3–4 满装精英可过 Boss"，恶魔领主 HP=666 作梗门槛。

## 4. 架构演进建议

- 现有分层**保留**，是健康的。
- 新增模块均挂 `game` 上下文、保持纯函数可测（参考 `merge.js`）：`recipes.js`、`cardex.js`、`economy.js`、`combat.js`、`monster.js`、`tech.js`。
- **测试基建**：原型阶段零测试。阶段 1 起应补 vitest，覆盖 `recipes` 命中、经济闸门、战斗结算——recipe 引擎膨胀后回归风险高。
- **配置外置**：所有卡牌/配方/数值集中 `config.js` + `recipes.js`，策划可改不碰逻辑。

## 6. 关键决策与开放问题

1. **品牌与主题（已拍板 2026-08-18）**：保留「牛牛农场」品牌，主体围绕牛——牛链为 recipe 引擎中央支柱，硬币唯一主源 = 卖牛；木材/围栏/银行卡链为存储与辅助。**不再复刻 Stacklands 浆果起点**，浆果/蓝莓丛降级为辅助安全垫。此决策已回写 GDD §3.3/§4.4/§4.5/§7。
2. **平台**：当前纯 web（Vite）。若未来要移动端，drag 交互需重做（触摸事件已在，但卡牌密度/屏幕尺寸要调），建议阶段 5 再议。
3. **是否做 DLC**：决定 D 信号达标与否，属发行决策，不在本规划设计范畴。
4. **测试基建**：原型零测试，阶段 1 起应补 vitest，否则 recipe 引擎膨胀后回归风险高。
