# 牛牛牧场 · 游戏音频系统设计

> 版本：v1.0（2026-08-19）｜作者：Game Audio Engineer
> 适用范围：H5 Web 版（Vite + 原生 ES Module），目标平台含移动端微信内置浏览器

---

## 1. 结论先行

- **引擎路线**：Web Audio API 原生实现。项目是零依赖纯 Web 工程，无 Unity/Unreal，FMOD/Wwise 不适用；但把中间件的工程纪律（事件命名 / 总线层级 / voice 预算 / 自适应参数）原样平移到 Web 实现，避免 Web 项目最常见的"散落 Audio() 调用 + 无预算 + 硬编码"乱象。
- **实现阶段**：第一阶段全程序化合成（零音频资产即可跑），第二阶段替换为采样资产。程序化方案保证游戏第一时间有声音，采样方案保证质量上限。
- **默认静音启动**（微信小游戏/浏览器 autoplay 政策）：首次用户手势（点击/拖拽）后初始化 AudioContext 并解禁，之后所有事件才可发声。这是合规红线，不是可选项。

## 2. Sonic Identity（声音身份）

三个形容词，所有声音设计决策用它们过审：

| 形容词 | 含义 | 落地准则 |
|---|---|---|
| **温暖 (Warm)** | 木质、圆润、少刺耳高频 | 采样优先打击乐/木琴/拨弦；合成用三角波+低通，避免方波 |
| **手绘感 (Handmade)** | 与美术手绘风同源，不追求"大片"质感 | SFX 带轻微音高随机（±5%），避免电子味一致性 |
| **轻盈 (Light)** | 休闲游戏，不制造压力 | 全局音量克制，UI 事件音量 < SFX < 音乐；无长时间高频轰炸 |

**反例（不过审）**：刺耳电子合成器警报、密集打击乐、任何超过 3 秒的同质循环噪音。

## 3. 事件命名规范（Web 版）

不用 FMOD 的 `event:/` 路径（无中间件），但保持**等价的命名纪律**：`[类别].[子类].[事件]`，全小写英文，禁止在游戏代码里硬编码任何资产路径——所有触发走 `sfx.play("...")` 事件名。

```
# 事件清单（第一阶段必做，标 ★ 的为高频核心反馈）
sfx.ui.click           ★ 按钮/底部导航点击
sfx.ui.open            弹窗打开
sfx.ui.close           弹窗关闭
sfx.ui.error           购买失败/金币不足
sfx.ui.task            任务完成
sfx.card.grab          ★ 抓起卡片
sfx.card.drop          ★ 放下卡片（落桌）
sfx.card.stack         卡片并入堆（轻微 thunk）
sfx.gather.wood        ★ 采木完成
sfx.gather.stone       ★ 采石完成
sfx.gather.berry       采蓝莓完成
sfx.gather.ore         采矿完成
sfx.craft.finish       ★ 制作/建造/冶炼/烹饪完成（同一事件，音高区分）
sfx.eat                ★ 进食（咀嚼感）
sfx.feed               喂食成功
sfx.breed              繁殖（新生幼音，高八度可爱）
sfx.combat.hit          ★ 战斗命中（短促）
sfx.combat.kill         ★ 击杀怪物
sfx.combat.monster     怪物出现（夜间警报，低音）
sfx.money.sell         出售成功（金币声）
sfx.money.gain         任务奖励
sfx.night.start        入夜（氛围过渡提示）
sfx.day.start          天明（鸟鸣感）
sfx.starve             饿死（下行音）
sfx.pack.open          新手卡包/卡包购买打开
sfx.badge              暂停/恢复（短促双音）
```

**UI/SFX/Music 三总线分离**（见 §4），UI 音量独立于游戏 SFX，方便后期加"仅音乐"或"仅音效"设置。

## 4. 总线架构（Web Audio Graph）

```
                    ┌─────────────────────────┐
  sfx.play() ──────▶│ GainNode: SFX Bus (0.9) │──┐
                    └─────────────────────────┘  │
                    ┌─────────────────────────┐  │    ┌──────────────┐    ┌───────────┐
  music.play() ────▶│ GainNode: Music Bus(0.5)│──┼───▶│ Master Gain  │───▶│ Destination│
                    └─────────────────────────┘  │    │  (0.9)       │    └───────────┘
                    ┌─────────────────────────┐  │    └──────────────┘
  ui.play() ───────▶│ GainNode: UI Bus (0.7)  │──┘
                    └─────────────────────────┘
```

- **一个 AudioContext 全局单例**，不随弹窗/场景重建。
- 三条 bus + master，全部 GainNode 实现，设置页可调（master / music / sfx 三滑杆 [PLACEHOLDER 待 UI 排期]）。
- **禁止**在游戏逻辑代码中直接 `new Audio()` / 直接操作 `audioCtx` —— 全部收敛到 `audio.js` 一个模块。

## 5. Voice 预算与性能（移动端红线）

| 项 | 值 | 说明 |
|---|---|---|
| 最大并发 voice | **16** | 超限优先偷最老的，UI 永不偷（优先级 0） |
| 单音最长 | SFX ≤ 2s；音乐/氛围 循环 | 程序化合成全部短促 |
| 合成开销 | 振荡器 ≤ 4 个/事件 | 打击类用 NoiseBuffer 复用（一次生成全局共享） |
| AudioContext 恢复 | 首次手势后 | iOS/微信必须，否则无声 |
| 采样率 | 44100（默认） | 不做 resample，省 CPU |

**设计决策**：Web 版不搞空间音频（2D 顶视角卡牌游戏无空间需求），全部 2D 播放——这是刻意的取舍，不是遗漏。

## 6. 自适应音乐系统（昼夜双态 + 强度参数）

音乐不用单曲循环，用**分层循环（stem-based）**：

```
Music 结构：
  base 层（木琴拨弦 + 轻打击，2 小节循环）── 全天播放，疲劳度低
  night 层（低音 drone + 稀疏铃音）─────── 仅夜晚，与 base 交叉淡入 2s
  tension 层（高频 pulse，威胁时进入）────── 夜间有怪物存活时叠加
```

- **参数 1 `TimeOfDay`（0=昼 1=夜）**：由 `game.state.phase` 驱动，变化时触发 `sfx.night.start` / `sfx.day.start` 提示音。
- **参数 2 `ThreatLevel`（0~1）**：夜间场上怪物数量映射——`monsterCount / 6`，封顶 1。>0.3 时 tension 层淡入。
- **过渡规则**：全部交叉淡入 ≥ 2 秒，禁止硬切（除死亡结算等特殊节拍点）。
- **音乐资产**：第一阶段用程序化音序器（Web Audio 振荡器 + 简单 pattern，Base/Night 两层）先跑通结构；第二阶段替换为 2 首 30s+ 循环采样（作曲外包或授权素材 [PLACEHOLDER]）。

| 底部导航点击 | sfx.ui.click | 所有 navbtn/iconbtn |
| 弹窗打开/关闭 | sfx.ui.open/close | overlay 挂载/卸载 |
| 购买失败 | sfx.ui.error | buyPack 金币不足分支 |
| 任务达成 | sfx.ui.task | checkTasks 内 |
| onDown 抓卡 | sfx.card.grab | drag.js onDown |
| onUp 落卡 | sfx.card.drop / sfx.card.stack | onUp 判断是否并入堆 |
| 采集产出（_drops 消费） | sfx.gather.* | 按 recipe id 映射到材料 |
| doAction 完成后 | sfx.craft.finish | 音高按 kind 微调（build 低音/食用高音） |
| 喂食 | sfx.feed | feedUnit 内 |
| 繁殖 | sfx.breed | breed 配方执行 |
| fightStep 命中 | sfx.combat.hit | 每伤害结算 |
| killMonster | sfx.combat.kill | 击杀分支 |
| spawnMonsters | sfx.combat.monster | 夜间刷怪 |
| sellCards 出售成功 | sfx.money.sell | 价格>0 分支 |

**实现原则**：SFX 触发代码写进既有系统函数（systems.js/merge.js/drag.js），通过 `audio.js` 导出的事件名调用——与游戏状态解耦，游戏逻辑不关心声音怎么出。

## 8. 程序化合成方案（第一阶段，零资产）

全部用 Web Audio 原生节点合成，短促、低成本：

**参数化变体原则（2026-08-19 增补）**：抓起/放下不按卡做资产，用 3 个声学参数驱动同一个合成器——`weight`（音高基准+放下音量）、`hardness`（滤波明亮度+金属泛音）、`organic`（活物颤音）。类别默认值见下表，个别卡用 `META.audio` 覆盖。**抓起与放下音量规则相反**：抓起=轻物响/重物轻，放下=重物响/轻物轻，制造"质量感"。

| cat | weight | hardness | organic |
|---|---|---|---|
| unit | 0.35 | 0.30 | 1.0 |
| node | 0.85 | 0.90 | 0 |
| res | 0.50 | 0.60 | 0 |
| food | 0.20 | 0.20 | 0.4 |
| build | 0.75 | 0.70 | 0 |
| item | 0.40 | 0.80 | 0 |
| life | 0.50 | 0.30 | 1.0 |
| mon | 0.60 | 0.50 | 0.6 |

| 音效 | 合成配方 |
|---|---|
| click / open / close | 短噪声 burst 300ms + 低通 2kHz，音高 400→300Hz |
| grab | 三角波 180Hz，0.08s 衰减，音高 -5% 随机；**参数化**：freq=180−weight×90，bright=800+hardness×3200，vol=0.9−weight×0.4，decay=0.08+weight×0.06，organic>0.5 加 8Hz 颤音 |
| drop / stack | 噪声 burst 150ms + 三角波 120Hz thunk；**参数化**：vol=0.3+weight×0.6（重物响），decay=0.1+weight×0.2，hardness>0.7 加金属泛音（短正弦泛音列） |
| gather.wood | 木鱼感：三角波 440Hz 两次敲击（60ms 间隔） |
| gather.stone | 低噪声 + 正弦 220Hz 单次，衰减 0.3s |
| craft.finish | 上行琶音 3 音（C-E-G），按 kind 移调 |
| eat | 短促双噪声（咀嚼），150ms |
| combat.hit | 方波 100Hz 30ms（短促、低音量） |
| combat.kill | 下行滑音 400→150Hz + 噪声 0.4s |
| money.sell | 高频双音 880→1320Hz（金币感） |
| night.start | 低音 drone 150Hz 进入 + 风噪 |
| breed | 高八度 C6-E6 上行双音 |

**全局共享**：NoiseBuffer 生成一次缓存，所有打击类复用同一 buffer（memory 友好）。

## 9. 文件结构与接入点

```
src/audio.js          # 音频引擎：context/总线/play()/事件表/合成器（全部音频逻辑）
src/config.js         # 不改（音频配置独立在 audio.js 内，避免耦合）
main.js               # 首次手势 → audio.init() 解禁
game.js               # 暂停时 audio.pauseAll()（仅暂停音乐，SFX 不排队）
systems.js / merge.js / drag.js / modals.js   # 埋触发点（见 §7 映射）
index.html            # 无需引第三方库，无 CDN 依赖
```

**接入顺序（按依赖排）**：
1. `audio.js` 骨架（context + bus + play + 事件表 + 首 5 个高频音：click/grab/drop/gather.wood/craft.finish）
2. 埋点：drag.js（抓/放）、systems.js（采集/建造/喂食）、modals.js（UI）
3. 自适应音乐：昼夜分层循环
4. 战斗/怪物/饿死等低频事件补齐
5. [可选] 采样替换 + 三总线音量设置 UI

## 10. 失败信号（音频实现验收）

| 级别 | 失败定义 | 处理 |
|---|---|---|
| A | 移动端首次进入完全无声（autoplay 被拦未恢复） | 触发点漏接手势 init |
| B | 高频操作下声音卡顿/爆音 | voice 预算失效，回查 steal 逻辑 |
| C | 同一动作声音听感僵硬（每次一模一样） | 音高随机化未生效 |
